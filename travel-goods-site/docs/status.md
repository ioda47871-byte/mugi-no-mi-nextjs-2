### なぜ実データが 0 件なのか

実装環境から**外部サイトへのHTTPSアクセスが遮断されている**ためです。次のドメインへの接続をすべて確認し、いずれも到達できませんでした。

- メーカー公式サイト（仕様の確認先）
- 航空会社の公式案内（`www.ana.co.jp` など、モバイルバッテリーの取り扱いの確認先）
- アフィリエイト各社（`affiliate.amazon.co.jp` など、規約・リンク形式の確認先）

計画書 5-2節「値が不明なら `null`。0、推定値、類似商品の値で穴埋めしない」および 0節「存在しない値を作って本番に混ぜない」に従い、**確認できない仕様・出典URL・確認日を本番データへ書き込んでいません**。訓練データの記憶から実在メーカーの数値を書くことは、出典と確認日を伴わない推定値の記入にあたるため行いませんでした。

### 代わりに用意したもの

`datasets/demo/` に、**実在しない架空メーカー・架空商品**によるデモデータ 30 件と記事 10 本を用意しました。これにより、絞り込み、比較表、不明値の扱い、購入リンクの抑制、公開判定、SEO・構造化データまで、すべての機能を実際に動かして確認できます。

デモデータには次の安全策をかけています。

- 全ページ最上部に「デモデータ表示中」の注意書きを常時表示。
- `SITE_MODE=production` ではデモデータセットを読み込めない（`src/lib/catalog/load.ts` で例外）。
- `check:release` がビルド成果物を走査し、デモ文言・`example.invalid`・テスト用ASINの混入を検出して失敗させる。
- デモの販売先リンクはすべて `unverified` / `unavailable`。**架空商品への購入リンクは1本も生成されません**。

### 本番データを入れるために必要なこと

いずれか1つで着手できます。

1. 実装環境の外部アクセス許可（メーカー公式ドメインへの HTTPS）。
2. メーカー公表仕様ページの内容（URL・該当箇所・確認日を添えて）の提供。
3. 楽天アフィリエイト管理画面で発行した紹介URLの提供（商品の型番・容量つき）。

手順は `docs/operations.md` の「商品を追加する」を参照してください。

## 6. 設計上の判断メモ

| 判断 | 理由 |
|---|---|
| Next.js 15.5.24 / React 19 / TypeScript 5.9 / Tailwind 3.4 を固定 | 最新メジャー（Next 16 / TS 7 / Tailwind 4）は変更が大きく、静的出力の実績を優先した |
| `output: 'export'` の静的出力 | 実行時DB・SSR・ISR・APIルートを持たず、どの静的ホストにも移せるようにするため（計画書 8節） |
| Markdown は自前の限定パーサー | `dangerouslySetInnerHTML` を使わず、本文から任意のHTML・JSが実行される経路を作らないため |
| 購入リンクの解決はビルド時のみ | 紹介IDの判定をブラウザ側の分岐に依存させないため |
| データセットを production / demo に分離 | 架空データが本番に混ざる経路を、設定ではなくディレクトリと検証で塞ぐため |
| 単体テスト用データは `tests/fixtures/` に分離 | 本番・デモのどちらにも混ざらないようにするため（計画書 Task 2） |
