## 2. 出典の入手経路

**取り込み済みの仕様値は、どれも各メーカーの公式ページへ自分で接続して取ったものではありません。**
取り込み当時の環境では外部ドメインへの HTTPS が遮断されていたため、資料の提供を受けました。

> 2026-08-31 の点検で、実行環境によっては外部へ到達できることが分かりました（「4. 購入ボタン（CTA）の
> 確認状況」の「外部への到達性が変わりました」を参照）。ただし**取り込み済みデータの入手経路は
> 書き換えません。** 自分で取得し直した値だけを `direct-fetch` として記録します。

これを取り違えないよう、`Source` に入手経路を機械可読で記録しています。

| フィールド | 値 | 意味 |
|---|---|---|
| `provenance` | `provided-document` | 別環境で調査された資料からの取り込み |
| `checkedAt` | `2026-08-31` | **資料に記載された「公式ページを確認した日」** |
| `importedFrom.document` | `datasets/production/research-materials/…` | 根拠資料の保管場所 |
| `importedFrom.importedAt` | `2026-08-31` | **このリポジトリへ取り込んだ作業日** |
| `automatedFetch` | `unverified` | 自動取得の可否は未確認（資料の提供は許可ではない） |
| `llmInput` | `unverified` | 原文を外部AIへ渡す権限は未確認 |

検証で次を強制しています。

- `provided-document` なのに `importedFrom` が無ければエラー
- `direct-fetch` なのに `importedFrom` があればエラー（自力確認と偽れない）
- 取込日が未来ならエラー

画像は権利確認ができていないため、**4件とも `image: null`**（文字主体のカード）です。

### 「照合済み」の判断根拠を記録するようにしました

自動取得を入れたことで、`verified` に2種類の意味が混ざるようになりました。
両者を混同しないよう、`MerchantLink.verificationMethod` に根拠を必ず記録します。

| 値 | 意味 |
|---|---|
| `visual` | 人がリンク先を開いて商品・サイズ・色を確認した |
| `identifier-match` | 型番・JANの一致で判断した（リンク先は開いていない） |

- `status: verified` で根拠が無いデータは**検証エラー**になります。
- 自動取得ジョブが作るリンクは**必ず** `identifier-match` です。目視確認にはなりません。
- `npm run link:set --verify` は `--visual-check` か `--identifier-match` の指定が必須です。
- `validate:content` が内訳を出します（現在: 照合済み 1 件／目視確認 1・型番一致のみ 0）。

### rel から noreferrer を外した件

楽天が発行するリンクコードが `rel="nofollow sponsored noopener"` で `noreferrer` を
含んでいなかったため、こちらも合わせました。リファラを落とすと成果の判定に
影響する可能性があるためです。タブナビング対策は `noopener` だけで足ります。
成果判定の実際の仕組みは各社の非公開情報のため確認できていません。
あわせて、遷移時に当サイトのページURLが販売先へ伝わることをプライバシーページに明記しました。

## 11. 設計上の判断メモ

| 判断 | 理由 |
|---|---|
| `sizeBasis` / `measurementState` / `alternateMeasurements` を追加 | 「ハンドルを除く」「拡張時」の値を無条件の外寸として格納しないため |
| `Source.provenance` / `importedFrom` を追加 | 提供資料からの取り込みを「自分で接続して確認した」と記録させないため |
| `jan` を追加 | 販売先の照合と楽天での商品検索に使うため（架空値は入れない） |
| バッテリーを `review` で保持 | 安全告知の追加確認が済むまで公開しない。仕様データの取り込みは進める |
| CTA確認を `.preview/` へ出力 | 本番の静的出力に混ぜないため。Playwright が `test-results/` を消すため別ディレクトリ |
| e2e をデータセット別に分離 | デモは絞り込み・0件・下書き非公開を厚く、本番データは寸法条件と件数を確認 |
