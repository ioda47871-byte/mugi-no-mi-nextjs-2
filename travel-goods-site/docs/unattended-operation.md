# 無人運用はどこまでできるか

「最終的に何も関与しなくてもサイトが回り続ける」ことを目標にした場合の、
できること・できないこと・その理由をまとめます。

結論を先に書きます。

> **維持は無人化できます。成長は無人化できません。**

---

## 1. すでに無人で回るもの

| 処理 | 頻度 | 人の関与 |
|---|---|---|
| データ検証・型検査・テスト・ビルド | プッシュのたび | なし |
| 定期点検（期限切れ・リンク切れ・整合性） | 週1回 | **何も無ければ通知なし** |
| 楽天からの紹介URL取得 | 手動または定期 | なし（結果はPR） |
| 商品候補の収集 | 手動または定期 | なし（未確認として保存） |
| 販売終了の検出 | 定期点検時 | なし（表示から外すだけ） |

点検で何も見つからなければ、Issue も通知も作られません。
見つかったときだけ Issue が立ち、直ると自動で閉じます。

**つまり「毎回見る」必要はありません。「呼ばれたら見る」で回ります。**

---

## 2. 人が要るもの（回数は商品・記事の数に比例）

| 作業 | 頻度 |
|---|---|
| リンク先を開いて商品・サイズ・色を確認 | 商品1件につき1回 |
| 新商品の採用（仕様と出典の登録） | 商品1件につき1回 |
| 記事を書く・公開判定 | 記事1本につき1回 |
| 安全情報（回収・リコール）の確認 | 期限が来たとき |

**運用の頻度には比例しません。** 商品を増やさなければ、ここはゼロに近づきます。

---

## 3. 無人化しないもの（できるが、しない）

技術的には自動化できますが、意図的にしていません。

### 新商品の自動公開

楽天APIが返すのは**販売情報**であって、メーカーの公表仕様ではありません。
重量・外寸・容量を出典なしで載せることになります。
比較サイトとしての価値が無くなり、誤った数値を配ることになります。

### 記事の自動生成・自動公開

Googleのスパムポリシーは、検索順位の操作を主目的とする大量生成を対象にしています。
AIを使うこと自体は問題になりませんが、**確認していない内容を出し続けると**
サイト全体の評価が落ちます。復旧には時間がかかります。

### 安全情報（回収・リコール）の自動判定

メーカーの告知は形式がばらばらで、自動判定は誤検知も見逃しも起こります。
モバイルバッテリーで見逃した場合の影響が大きすぎます。
点検は「確認期限が来た」と知らせるところまでを機械が行い、判断は人が行います。

### 目視確認の自動化

自動取得したリンクは `identifier-match`（型番・JANの一致）として記録され、
**目視確認には昇格しません。** 色違い・セット品の取り違えは型番だけでは防げません。

---

## 4. 無人化できない構造的な理由

自動化の巧拙とは別に、**責任の所在**が人に紐づいています。

| 事項 | 内容 |
|---|---|
| アフィリエイト規約 | 掲載内容の責任は運営者にあります。アカウント停止は自動化では防げません |
| 広告表示の義務 | ステルスマーケティング規制により、広告であることの表示が必要です |
| 運営者情報 | 実在する運営主体と連絡先の掲載が求められます |
| 訂正対応 | 誤りの指摘に応じる主体が必要です |

サイトが「回り続ける」ことと、「誰も責任を負わない」ことは別です。
前者は達成できます。後者は達成できません。

---

## 5. 現実的な到達点

商品を増やすのをやめた時点で、運用はほぼ無人になります。

- 週1回の点検が動き、**何も無ければ何も起きない**
- 安全情報の確認期限（バッテリーは90日）が来たら Issue が立つ
- 販売終了を検出したら、その商品のリンクだけ静かに画面から消える
- 記事とサイトはそのまま動き続ける

**年に数回、Issue が立ったときに見る**——これが現実的な下限です。

商品や記事を増やしている間は、1件ごとに人の確認が入ります。
これは自動化の不足ではなく、比較サイトとして成立させるための条件です。

---

## 6. 使い方

```bash
# 手元で点検する（外部アクセスなし）
CATALOG_DATASET=production npm run audit

# 機械可読
CATALOG_DATASET=production npm run audit -- --json

# 確認事項でも失敗させる（厳しめ）
CATALOG_DATASET=production npm run audit -- --fail-on attention

# 販売終了の検出（楽天APIキーが必要）
CATALOG_DATASET=production npm run rakuten:sync -- --mode audit
CATALOG_DATASET=production AUTOMATION_ENABLED=true \
  npm run rakuten:sync -- --mode audit --apply   # 表示から外す（削除はしない）
```

### 点検している項目

| 項目 | 既定の期限 | 深刻度 |
|---|---|---|
| モバイルバッテリーの安全情報の再確認 | 90日 | **要対応** |
| 公開記事が未公開商品を参照 | — | **要対応** |
| 商品仕様の確認日（最も古い値で判断） | 180日 | 確認 |
| 出典の確認日 | 180日 | 確認 |
| 販売先リンクの照合日 | 180日 | 確認 |
| 目視未確認のまま表示しているリンク | — | 確認 |
| 購入リンクが無い公開商品 | — | 確認 |
| 公開記事の実質更新日 | 365日 | 確認 |
| 未処理のまま放置された商品候補 | 30日 | 確認 |

期限は `src/lib/catalog/audit.ts` の `DEFAULT_THRESHOLDS` で調整できます。
