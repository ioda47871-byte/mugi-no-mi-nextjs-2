# 根拠資料の保管

`sources.json` の `provenance: "provided-document"` が指す提供資料を、原文のまま保管します。

| 資料ファイル | 提供日 | 内容 | 資料に記載された確認日 |
|---|---|---|---|
| `2026-08-31-travel-goods-next-steps.md` | 2026-08-31 | 実商品4件（スーツケース／ポーチ／リュック／モバイルバッテリー）の公式仕様の要約と出典URL | 2026-08-31 |

## 資料の置き方（保存したページを渡す場合）

外部アクセスが遮断されている環境では、Claude はメーカーの公式ページを開けません。
その場合、**公式ページの保存物をこのディレクトリに置いてください。**

保存のしかた（どれでも構いません）:

- ブラウザで公式の製品ページを開き、**PDFとして保存**（印刷 → PDF）
- ブラウザの「ページを保存」で HTML として保存
- 仕様表の部分をテキストで貼り付けたファイル

ファイル名の例: `2026-09-01-elecom-BMA-TRCS01MBK.pdf`

**販売店のページではなく、メーカー公式のページを保存してください。**
販売店の説明文は編集の根拠に使いません。

置いていただければ、Claude が読んで商品データを作ります。

## 取り扱いのルール

- **この実装環境から各メーカーの公式ページへは接続していません。**
  何をもってその値を知ったかを `provenance` で機械可読に記録します。

| `provenance` | 意味 | `checkedAt` の意味 |
|---|---|---|
| `direct-fetch` | この環境から公式ページへ接続して確認した | ページを開いた日 |
| `archived-primary-source` | **公式ページの保存物（PDF/HTML）を読んで取り込んだ** | 保存物が取得された日 |
| `provided-document` | 第三者がまとめた資料から取り込んだ | 資料に記載された確認日 |

強さは `direct-fetch` ≒ `archived-primary-source` > `provided-document` です。
保存物は一次資料そのものなので、まとめ資料より確かです。
`direct-fetch` 以外は `importedFrom`（元資料のパスと取込日）が必須で、
無いと検証エラーになります。
- `checkedAt` は**資料に記載された「公式ページを確認した日」**です。
  `importedFrom.importedAt` は**このリポジトリへ取り込んだ作業日**です。両者は別の日付です。
- 資料の提供は、**自動取得の許可でも画像利用の許可でもありません。**
  `automatedFetch` と `llmInput` は `unverified` のままです。
- 販売先の照合・紹介URLの発行は別作業です。資料に商品ページURLが載っていても、
  それは紹介URLではありません。

新しい資料を受け取ったら、このディレクトリに原文を追加し、上の表に追記してください。
**資料なしで `provided-document` の出典を作らないでください。**
